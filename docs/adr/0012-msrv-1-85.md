# 0012. Minimum supported Rust version 1.85; CI on 1.89

- Status: Accepted
- Date: 2026-11-20
- Deciders: Maintainer
- Related: BL-004, BL-014, ADR-0009

## Context
`.tool-versions` pinned Rust 1.81.0, but the project no longer builds on it: locked dependencies
need edition 2024 (`globset` via `scalar-doc` → `tera`), and `rquickjs` 0.11 needs Rust 1.85.
`cargo +1.85.0 build --locked --all-targets` succeeds. Everyone builds locally with 1.89.0, and
CI (BL-004) runs clippy with `-D warnings`, so a floating `stable` would break CI whenever a new
lint ships. `.tool-versions` is gitignored, so CI cannot read it anyway.

## Decision
- **MSRV is Rust 1.85**, declared as `rust-version = "1.85"` in `Cargo.toml`. Cargo then refuses
  older toolchains with a clear message, and crates.io shows it.
- **Development and the CI gate use Rust 1.89.0**, pinned in `.github/workflows/rust.yml`
  (`RUST_TOOLCHAIN`). Bump it deliberately, together with any clippy fixes.
- A separate CI job builds all targets on 1.85 with `--locked`, so the MSRV stays true.
- Raising the MSRV, or moving to edition 2024, needs a new ADR (BL-014 covers the edition question).

## Consequences
- + The declared minimum matches reality; downstream users get a clear error below 1.85.
- + Lint changes arrive only when the pinned toolchain is bumped.
- − Two toolchains in CI (1.85 build, 1.89 gate); a dependency update that needs a newer Rust
  fails the MSRV job and forces an explicit decision.
- Local `.tool-versions` (untracked) should say `rust 1.89.0`.

## Alternatives considered
- Keep 1.81 — impossible without downgrading dependencies.
- Track `stable` in CI — breaks `-D warnings` on every new clippy lint.
