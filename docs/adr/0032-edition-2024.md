# 0032. Edition 2024, MSRV unchanged, std LazyLock, rustfmt style 2021 for now

- Status: Accepted
- Date: 2026-11-21
- Deciders: Maintainer
- Related: BL-014, ADR-0012, ADR-0020, ADR-0028

## Context
The crate and the `fuzz/` workspace were on edition 2021. ADR-0012 set the MSRV to 1.85 and left
the edition to BL-014, which the maintainer queued. Rust 1.85 is the first release with edition
2024, so the move needs no MSRV bump. Global state used three mechanisms: `lazy_static!`
(function registry, builtin dispatch table), `once_cell::sync::Lazy` (HTTP expression cache) and
`OnceLock` (CORS headers, server eval limits, the fuzz variable map). `std::sync::LazyLock` is
stable since 1.80 and covers the first two. Formatting with style edition 2024 would reorder
imports and rewrap code across most files, which would bury the edition change in noise.

## Decision
- **Edition 2024** for the root crate and `fuzz/`. The migration is `cargo fix --edition`,
  reviewed by hand: rewrites that only guard against a 2024 change that does not apply here
  (`if let` → `match` where the `else` branch never uses the lock guard, `+ use<>` on
  return-position `impl Trait` that no caller keeps past the borrow) are reverted. What stays:
  explicit `unsafe {}` blocks inside the test allocator's `unsafe fn`s
  (`unsafe_op_in_unsafe_fn`), and the `gen` identifier renamed (now a reserved keyword).
- **MSRV stays 1.85** (ADR-0012). The CI `msrv` job keeps building all targets on 1.85.0.
- **`LazyLock` policy**: a static whose value is computed from nothing but code uses
  `std::sync::LazyLock`. A value set once at runtime from configuration (CORS headers, the server
  eval limits resolved at start-up) keeps `OnceLock` with an explicit `init`/`set`. No
  `lazy_static` or `once_cell` as direct dependencies; `once_cell` may still arrive transitively.
- **rustfmt keeps `style_edition = "2021"`** (`rustfmt.toml`), so `cargo fmt --check` shows no
  churn. Switching to style edition 2024 is a later, separate, fmt-only commit with no other
  change in it.
- The `unsafe` allowlist (`tests/unsafe_scope.rs`, ADR-0020) is unchanged: the migration adds no
  `unsafe` under `src/`.

## Consequences
- + Current language defaults (RPIT lifetime capture, `if let` and tail-expression temporary
  scopes, `unsafe extern`, unsafe `set_var`) apply to new code; no code here calls
  `std::env::set_var` or `remove_var`.
- + Two fewer direct dependencies; one way to write a lazy static.
- + Edition 2024 implies resolver 3, which prefers dependency versions whose `rust-version` fits
  the MSRV when the lock file is updated.
- − Code is edition 2024 but formatted in the 2021 style until the fmt-only commit lands.
- ADR-0007 still describes the registry as a `lazy_static`; the mechanism changed, the design did
  not.

## Alternatives considered
- Stay on edition 2021 — no cost now, but the gap to current idioms and lints keeps growing.
- Reformat with style edition 2024 in the same change — mixes a mechanical reformat of most files
  into a toolchain change and makes review and `git blame` harder.
- Keep `once_cell` — std now has the same types; one fewer dependency to audit.
